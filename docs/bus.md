# Общая связь PuzzleBus

```text
ESP32 master -- UART 9600 -- wires -- I²C 100 кГц -- simon     0x11
                                              -- labyrinth 0x12
```

Все четыре прошивки подключают локальную библиотеку через
`lib_deps = symlink://../puzzle_bus`. Репозитории должны лежать рядом:

```text
MPS_course/
  puzzle_bus/
  wires/
  simon/
  labyrinth/
  master/
  web/
```

Библиотека не копируется в исходники прошивок. Изменения её файлов используются
при следующей сборке. Ссылка на удалённый репозиторий пока не требуется.
Веб-сервер не является прошивкой и не использует C++-библиотеку.

## Ответственность компонентов

- PuzzleBus::PuzzleNode хранит раунд, состояние и счётчики ошибок.
- PuzzleBus::AvrTwiNode обслуживает ведомый TWI и единственный TWI_vect.
- PuzzleBus::PuzzleMaster обнаруживает модули, повторяет команды и учитывает события.
- wires реализует аппаратный Transport и переводит события в UART ESP32.
- PuzzleBus/UartProtocol.h задаёт общий разбор UART для wires и master.
- master сохраняет таймер, штрафы, звук и связь с вебом.

В master выбран `custom_puzzle_bus_core_only = yes`: прямого обмена I²C там нет,
поэтому ESP-IDF I²C-драйвер не собирается. Фреймворк ESP32 в этой задаче не менялся.

## Пакет и команды

I²C использует только **22-байтовый** формат PuzzleBus: сигнатура, версия,
операция, тип, 64-битный ID, сид, сложность, состояние, два накопительных
16-битных счётчика ошибок и CRC-16. Порядок полей задаёт библиотека,
структуры C++ напрямую в шину не отправляются.

Старый 20-байтовый формат удалён. wires, simon и labyrinth нужно обновить
согласованно. Старые прошивки с новым форматом несовместимы.

Новый GENERATE переводит узел в Preparing. Игровой код создаёт задание
и вызывает ready(), после чего состояние становится Playing.
Повтор одинакового ID и параметров не сбрасывает игру. Другие параметры
при том же ID и меньшие ID отвергаются. Reset разрешает начать нумерацию заново.

Stop останавливает текущий незавершённый раунд. Уже полученные Solved/Failed
сохраняются, включая индикацию результата. Reset очищает раунд и возвращает
Waiting. Оба счётчика насыщаются на 65535.

Шлюз опрашивает один адрес каждые BUS_POLL_MS (по умолчанию 25 мс).
Три неудачных ответа подряд дают OFFLINE. После перезагрузки ведомой
шлюз повторяет текущее задание. Его параметры и прогресс остаются в RAM.

UART-строки сохраняют прежний вид:

```text
E:GENERATE:17:42:1
W:GENERATED:17
G:2:READY:17:0
G:2:ERROR:17:3
E:GACK:2:ERROR:17:3
G:3:SOLVED:17:0
E:GACK:3:SOLVED:17:0
```

ERROR и SOLVED повторяются до подтверждения. ESP32 учитывает накопительный
счётчик, поэтому повтор не повторяет штраф. Wires хранит собственный результат
через PuzzleNode и сообщает его прежними W:SOLVED / W:FAILED.

## Подключение

UART: ESP32 GPIO2 TX → wires D10 RX. Wires D11 TX → резистор 1 кОм →
ESP32 GPIO4 RX, из этой точки 2 кОм → GND. Земля общая.

I²C: A4 всех трёх Uno — SDA, A5 — SCL. Один комплект подтяжек 4,7 кОм
к 5V на шлюзе. Эти линии напрямую к ESP32 не подключаются.
Разные USB-источники питания объединяются по GND, не по 5V.

GPIO2 ESP32 — загрузочный пин. На время прошивки ESP32 линию к wires D10
отсоединяют. Распиновка игрового оборудования приведена в README каждого проекта.

## Проверки без плат

В папках wires, simon и labyrinth:

```powershell
pio run
python test/run_tests.py
```

В master: `pio run` и `python test/check_logic.py`.
В puzzle_bus: `python tests/run_tests.py`.

Тесты используют реальные игровые классы, общую библиотеку и модели периферии.
Электрические уровни, тайминги на физических линиях и ориентацию индикации
нужно проверить на стенде. Сборка и тесты не загружают прошивку на платы.
