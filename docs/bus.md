# Временное решение: общая шина UART/I²C

ESP32 остаётся ведущим модулем игры. Uno `wires` одновременно решает «Провода» и служит шлюзом: UART связывает её с ESP32, общая I²C-шина — с Uno `simon` и `labyrinth`.

```text
ESP32 -- UART 9600 -- Uno wires -- I²C 100 кГц -- Uno simon     (0x11)
                                            -- Uno labyrinth (0x12)
```

I²C находится только между Uno с логикой 5 В. ESP32 к SDA/SCL не подключается, поэтому преобразователь уровней I²C в этой временной схеме не нужен. На UART сохраняется существующий делитель Uno TX → ESP32 RX.

## Распиновка

| Соединение | Откуда | Куда |
|---|---|---|
| UART мастер → шлюз | ESP32 GPIO2 (TX) | wires D10 (RX) |
| UART шлюз → мастер | wires D11 (TX) | Через 1 кОм → узел GPIO4 ESP32 (RX); от узла 2 кОм → GND |
| I²C SDA | wires A4 | simon A4 и labyrinth A4 |
| I²C SCL | wires A5 | simon A5 и labyrinth A5 |
| Общая земля | GND ESP32 | GND всех Uno |
| Подтяжка SDA | Общая линия A4 | Через 4,7 кОм к 5V wires |
| Подтяжка SCL | Общая линия A5 | Через 4,7 кОм к 5V wires |

Один комплект внешних подтяжек на всю I²C-шину. Для первого стенда делайте короткие соединения. Питание можно оставить от отдельных USB: объединяется GND, линии 5V разных USB между собой не соединяются. SDA/SCL не подключаются к ESP32.

На `simon` кнопка 4 перенесена с A4 на D9, кнопка 5 — с A5 на D10. Вторые контакты кнопок подключаются к GND. Остальная периферия всех модулей остаётся на прежних пинах. На `labyrinth` D0/D1 остаются для USB-загрузки и отладки; общей шине они не нужны.

GPIO2 ESP32 — загрузочный пин. На время прошивки ESP32 размыкайте линию GPIO2 → wires D10; возвращайте соединение при выключенном питании. UART wires использует D10/D11, поэтому D0/D1 Uno остаются для USB.

## Запуск и поведение

1. Загрузить прошивки всех четырёх проектов. Каждый проект содержит собственные заголовки в `include/` и собирается независимо от соседних папок.
2. Включить платы и проверить в консоли ESP32 сообщения `I2C Саймон: подключён`, `I2C Лабиринт: подключён`.
3. В существующем веб-пульте отправить сид/сложность через подготовку задания «Провода». Имя веб-команды сохранено для совместимости, параметры теперь общие для всех трёх головоломок.
4. Нажать D21 на ESP32. Новый ID раунда и параметры передаются шлюзу и обеим I²C-головоломкам. При необходимости установить и запустить таймер веб-кнопками, как раньше.
5. На «Проводах» замкнуть все пять проводов; Саймон и лабиринт начинают работу после получения задания. До задания их игровая индикация выключена.

Повторная передача того же ID раунда не сбрасывает прогресс. Повторное нажатие D21 создаёт новый ID и перезапускает все три головоломки с текущими подготовленными параметрами. Изменение параметров в вебе само по себе не начинает новый раунд.

Саймон использует `randomSeed(seed + 1)` и исходные таблицы цветов/кнопок. Лабиринт выбирает схему `difficulty * 9 + seed % 9` из `LEVELS`: девять схем каждой сложности, старт и финиш берутся из выбранной записи. Одни и те же параметры дают одно и то же задание. После победы ведомые сохраняют результат и ждут новую команду; автоматический переход лабиринта к случайной схеме удалён.

Малые ошибки Саймона и лабиринта передаются накопительным счётчиком. ESP32 назначает за каждую новую ошибку штраф 5/10/15 секунд для лёгкой/средней/сложной сложности (`SMALL_PENALTY_SECONDS`). Повтор сообщения не повторяет штраф. Победа каждого модуля вызывает существующую мелодию победы. Большая ошибка «Проводов» по-прежнему даёт штраф 30 секунд и мелодию поражения. Время не становится отрицательным, сигнал окончания имеет приоритет.

## Протокол

- `uart_protocol.h` — существующий построчный обмен ESP32 ↔ wires.
- `module_bus.h` — общий формат I²C-пакетов и UART-событий шлюза.
- `puzzle_i2c.h` — почтовый ящик ведомой Uno и подготовленный ответ состояния.

I²C-пакет занимает 20 байт, включая сигнатуру, версию, тип модуля, операцию, 64-битный ID раунда, сид, сложность, состояние, 16-битный счётчик малых ошибок и CRC-16. Многобайтовые числа передаются младшим байтом вперёд. Формат укладывается в 32-байтовый буфер AVR `Wire`.

Операции: `GENERATE`, `RESET`, `STOP`, `STATUS`. Состояния: `WAITING`, `PLAYING`, `SOLVED`, `STOPPED`. В обычном сценарии шлюз посылает `GENERATE` и читает `STATUS`; RESET/STOP предусмотрены для дальнейшего управления протоколом и проверяются тестами, отдельные веб-команды для них не добавлены.

Обработчик `onReceive` только копирует входящий пакет; разбор CRC и генерация игры происходят в `loop()`. `onRequest` возвращает заранее подготовленный снимок состояния. UART, Serial, управление светодиодами и генератор случайных чисел из I²C-обработчиков не вызываются.

Шлюз по очереди опрашивает один адрес каждые 25 мс (каждый модуль — примерно раз в 50 мс без учёта остальных действий). Таймаут I²C — 2,5 мс с восстановлением контроллера. Отсутствие трёх корректных ответов подряд помечает модуль как недоступный. При появлении модуля или его сбросе шлюз передаёт ему текущую конфигурацию повторно.

События шлюз → ESP32:

```text
G:2:ONLINE:0:0
G:2:READY:17:0
G:2:ERROR:17:3
G:3:SOLVED:17:0
G:3:OFFLINE:17:0
```

Типы: `2` — Саймон, `3` — лабиринт. Далее событие, ID раунда и счётчик. ERROR/SOLVED повторяются раз в 500 мс до ответа `E:GACK:<module>:<event>:<round>:<counter>`. При росте счётчика новая ошибка отправляется сразу. ONLINE/OFFLINE/READY — диагностические уведомления без подтверждения. События самих «Проводов» сохраняют прежний формат `W:...`.

ACK означает приём события мастером. ESP32 отдельно помнит результат и счётчик каждого модуля для активного раунда, повторно подтверждает события без повторного штрафа или мелодии. Старые раунды подтверждаются, но не изменяют текущую игру.

## Ограничения временного решения

В текущей реализации два фиксированных I²C-адреса. Это прототип для трёх головоломок; поддержка восьми модулей и гарантированный общий цикл опроса до 100 мс из SyRS здесь не заявляются. UART работает на 9600 бод, его передача и обновление WS2812 задерживают цикл; реальное время отклика нужно измерить на стенде. Для окончательного интерфейса потребуется отдельное проектное решение.

Состояние шлюза и головоломок хранится в RAM. После потери питания головоломки получают текущий раунд заново, поэтому прогресс сбрасывается; история ошибок не восстанавливается. На ESP32 сохраняются существующие ID веб-команд и счётчик раундов, но не полный снимок игры. Счётчик ошибок одной ведомой насыщается на 65535. Автоматическое завершение всего раунда по результатам всех модулей в этой правке не добавлено: обрабатываются события каждой головоломки и существующий таймер.

Без подключённой периферии проверяются кодеки, маршрутизация и игровая логика; электрические уровни, взаимодействие прерываний Wire/SoftwareSerial/WS2812 и потерю связи нужно проверить на реальных платах. Прошивки автоматически на платы не загружаются.

## Сборка и проверки

Выполнять из папки этого проекта:

```powershell
pio run
python test/check_bus.py
```

Для проверок на компьютере нужен g++ в PATH. Тесты и вспомогательные файлы находятся внутри проекта; для проверки ESP32 сначала установите зависимости сборкой PlatformIO.

Копии протокола в разных проектах должны оставаться совместимыми. При изменении формата обновляйте include/module_bus.h и include/uart_protocol.h во всех четырёх прошивках, а include/puzzle_i2c.h — в проектах Uno.
